# QA/Art Launch Readiness Plan

대상 프로젝트: `Core Survivor: Cosmic Purge`  
대상 플랫폼: Godot 4.3, Android, Google Play 전용 2D survivor-like  
문서 상태: 실제 플레이 전 기준의 출시 준비 계획서. QA 1~3차는 실행 결과가 아니라 계획/차단 기준과 초기 예상 이슈를 정의한다.  
작성 역할: Visual Design Lead + QA Lead + Dev Lead 출시 준비 보조

## 공통 원칙

- 모바일 가독성을 전투 재미보다 우선한다. 플레이어 탄, 적 탄, XP, 아이템, 위험 장판, UI 피드백은 색상과 실루엣이 동시에 구분되어야 한다.
- 광고는 보상형 중심으로만 설계한다. 강제 전면 광고와 전투 중 광고 호출은 출시 차단 이슈다.
- IAP 5종은 광고 제거, 스타터 패키지, 프리미엄 코어 스킨, 특수 드론 패키지, 월간/재화형 패키지 후보로 제한한다. 전투 성능을 영구적으로 압도하는 Pay-to-Win 판매는 금지한다.
- 결제, 광고, 저장 데이터는 실패 경로가 정상 경로와 같은 수준으로 검증되어야 한다.
- 모든 QA 이슈는 다음 형식을 사용한다: 이슈명, 재현 단계, 기대 결과, 실제 결과, 심각도, 수정 담당, 재검증 결과.

## 단계별 산출물

### 단계 8: 아트 디렉션 확정

- 단계명: 8. 아트 디렉션
- 담당 에이전트: Visual Design Lead
- 목표: 밝은 카툰/SD 톤을 유지하면서 Android 소형 화면에서도 전투 판독이 가능한 시각 기준을 확정한다.
- 구현/기획 범위: 캐릭터/코어 실루엣, 적/탄/XP/아이템 색상 체계, 이펙트 밀도, UI 크기, SD 코어 진화 룰, 스토어 이미지 톤.
- 산출물: 모바일 아트 가이드, 색상/실루엣 구분표, 이펙트 밀도 제한, SD 코어 진화 가이드.
- 발견된 문제: 실제 빌드와 기기 테스트 전이므로 이펙트 누적, 발열, 저사양 기기 프레임 저하 가능성이 검증되지 않았다.
- 수정 지시:
  - 플레이어 탄: 청록/하늘/백색 계열, 얇은 밝은 코어와 짧은 잔상. 적 탄과 같은 빨강/주황 계열 금지.
  - 적 탄: 빨강/마젠타/주황 계열, 중심부 고채도, 외곽선 또는 경고 링 포함. 플레이어 탄 색상과 혼용 금지.
  - XP: 라임/초록 결정체, 크기 1단계 이상 차등, 수집 가능 오브젝트임을 외곽 광택으로 표시.
  - 아이템: 골드/보라/흰색 아이콘 실루엣. XP와 동일한 초록 단색 금지.
  - 적: 몸체는 따뜻한 색 또는 어두운 보색 실루엣, 탄과 겹칠 때 외곽선으로 분리.
  - 위험 장판/텔레그래프: 준비 단계는 황색, 발동 직전은 적색. 피해 판정 범위와 시각 범위 오차는 8dp 이하.
  - 이펙트 밀도: 일반 전투에서 불투명 이펙트가 화면의 25%를 넘지 않게 하고, 궁극기/보스 패턴 순간에도 35%를 넘지 않게 한다. XP와 적 탄을 가리는 파티클은 출시 차단.
  - 파티클 수명: 반복 탄막 잔상은 0.35초 이하, 폭발 잔상은 0.6초 이하를 기본값으로 둔다.
  - SD 코어 진화: 0~5단계로 실루엣을 키우되 핵심 얼굴/코어 위치는 유지한다. 단계 상승은 링, 날개, 위성 드론, 꼬리광, 문양 순으로 더하고 작은 장식 텍스트는 사용하지 않는다.
  - UI: 핵심 전투 버튼은 최소 48dp 터치 영역, 주요 숫자는 12sp 상당 미만 금지, 상태 이상/쿨다운은 색상만이 아니라 아이콘 변화도 제공.
- 성공 기준: 6인치급 1080p 기기에서 1초 안에 플레이어 위치, 적 탄, XP, 아이템을 식별할 수 있다. 스크린샷 축소 50%에서도 위험/보상 오브젝트가 혼동되지 않는다.
- 검증 방법: 전투 스크린샷 3종(일반, 보스, 이펙트 과밀)을 그레이스케일/색약 시뮬레이션/저해상도 축소로 확인하고, QA 1차에서 실제 플레이 판독성을 기록한다.
- 승인 상태: 계획 승인 대기. 첫 플레이 가능 빌드에서 재승인 필요.

### 단계 9: 개발 구조 검수 기준

- 단계명: 9. 개발 구조 검수 기준
- 담당 에이전트: Dev Lead
- 목표: Godot 4.3 Android 2D 프로젝트가 survivor-like 확장, 광고/IAP, 저장 안정성, QA 추적을 견딜 수 있는 구조인지 검수한다.
- 구현/기획 범위: 씬 트리, 오토로드, 데이터 리소스, 전투 루프, 풀링, 저장 시스템, 광고/IAP 어댑터, 빌드 설정, 로그/진단.
- 산출물: 개발 구조 체크리스트와 차단 기준.
- 발견된 문제: 아직 프로젝트 코드가 없으므로 구조 검수는 사전 기준으로만 정의한다.
- 수정 지시:
  - 전투 노드와 수익화 SDK 호출을 분리한다. 전투 중 노드에서 광고/결제 UI를 직접 호출하면 구조 차단.
  - `SaveManager`, `AdService`, `BillingService`, `RunState`, `MetaProgression`, `Settings`는 오토로드 또는 명확한 서비스 계층으로 분리한다.
  - 무기, 적, 아이템, 코어 진화는 Godot `Resource` 기반 데이터로 관리하고 밸런스 값은 스크립트 상수에 흩어두지 않는다.
  - 탄, XP, 데미지 숫자, 히트 이펙트는 풀링을 기본으로 한다. 전투 중 대량 `instantiate/free` 반복은 성능 차단 후보.
  - 저장은 버전 필드, 임시 파일 저장 후 교체, 로드 실패 시 백업 복구 경로를 가진다.
  - 광고 보상 지급은 광고 완료 콜백 이후 서버/SDK 결과 또는 로컬 검증 상태를 기록한 뒤 1회만 지급한다.
  - IAP는 구매 시작, 취소, 실패, 보류, 승인, 복원, 중복 지급 방지를 상태 기계로 관리한다.
  - QA용 빌드는 FPS, 메모리 경향, 저장 슬롯 버전, 광고/결제 모의 결과를 로그로 남긴다.
- 성공 기준: 새 콘텐츠 추가가 씬 복사/스크립트 분기 남발 없이 데이터 추가로 가능하고, 광고/IAP/저장 실패가 전투 진행을 깨뜨리지 않는다.
- 검증 방법: 코드 리뷰, 씬 트리 리뷰, Android 로그캣, Godot profiler, 저장 파일 강제 손상 테스트 계획 검토.
- 승인 상태: 계획 승인 대기.

### 단계 10: 구현 계획 검수

- 단계명: 10. 구현 계획 검수
- 담당 에이전트: Dev Lead + QA Lead
- 목표: 구현 순서가 QA 가능한 수직 조각을 만들고 출시 리스크를 조기에 드러내도록 조정한다.
- 구현/기획 범위: 마일스톤, 수직 슬라이스, 테스트 빌드 cadence, 광고/IAP sandbox, 저장 마이그레이션, 스토어 준비.
- 산출물: 구현 계획 검수 체크리스트.
- 발견된 문제: 실제 개발 일정과 담당 배분이 확정되지 않았다.
- 수정 지시:
  - 1차 수직 슬라이스는 조작, 적 스폰, 자동 공격, XP 수집, 레벨업 선택, 사망/결산, 저장까지 포함한다.
  - 광고/IAP는 후반에 붙이지 말고 mock 서비스부터 인터페이스를 고정한다.
  - Android 실기 테스트는 첫 전투 루프 완성 시점부터 시작한다. 에디터 플레이만으로 QA 단계 진입 금지.
  - 저장 데이터 포맷은 첫 내부 검수 전에 버전 번호를 부여하고 마이그레이션 정책을 문서화한다.
  - 스토어 정책 항목인 데이터 보안, 광고 ID, 결제 상품, 개인정보처리방침은 출시 직전이 아니라 QA 2차 전에 초안 완료한다.
- 성공 기준: 각 마일스톤이 설치 가능한 Android 빌드와 검증 항목을 가진다.
- 검증 방법: 구현 계획 리뷰 회의록, 빌드 산출물 확인, QA 체크리스트와 마일스톤 매핑.
- 승인 상태: 계획 승인 대기.

### 단계 11: 내부 검수

- 단계명: 11. 내부 검수
- 담당 에이전트: QA Lead + Dev Lead + Visual Design Lead
- 목표: QA 사이클에 넘기기 전 명백한 차단 결함을 제거한다.
- 구현/기획 범위: Android 설치/실행, 첫 세션 완료, UI/아트 판독성, 저장/불러오기, 광고/IAP mock, 크래시 로그.
- 산출물: 내부 검수 체크리스트와 진입/차단 기준.
- 발견된 문제: 실제 빌드 부재로 실행 검수는 대기 상태다.
- 수정 지시:
  - 첫 실행, 튜토리얼 또는 즉시 전투 진입, 3분 생존, 사망/보상, 재시작이 한 기기에서 끊기지 않아야 QA 1차 진입 가능.
  - Android 뒤로가기, 홈 전환, 화면 잠금/복귀, 네트워크 on/off 전환에서 저장 데이터가 손상되면 QA 진입 금지.
  - 전투 중 보상형 광고 버튼이 노출되더라도 광고 재생은 전투 종료/일시정지 안전 지점에서만 허용한다.
  - 구매 상품 5종은 테스트 상품 ID, 표시명, 가격 노출, 구매 제한, 복원 정책이 정리되어야 한다.
- 성공 기준: S0/S1 차단 이슈 없이 QA 1차 빌드를 배포할 수 있다.
- 검증 방법: 내부 smoke test 30분, 로그캣 확인, 저장 파일 백업/복원 수동 테스트, 스크린샷 판독성 리뷰.
- 승인 상태: 대기.

### 단계 12: QA 1차 체크리스트

- 단계명: 12. QA 1차 체크리스트
- 담당 에이전트: QA Lead
- 목표: 기본 게임 루프, 설치 안정성, 저장 안정성, 광고/IAP 실패 경로의 1차 차단 결함을 찾는다.
- 구현/기획 범위: Android 실기 2종 이상, 기본 전투 루프, UI 터치, 저장/로드, 광고 mock 또는 sandbox, 결제 sandbox.
- 산출물: QA 1차 계획/차단 기준, QA 1차 초기 예상 이슈.
- 발견된 문제: 실제 플레이 전이므로 결과값은 비워두고 예상 이슈만 선등록한다.
- 수정 지시:
  - S0/S1 이슈는 QA 2차 진입 전 수정한다.
  - 색상 혼동, 저장 손상, 결제 중복 지급, 광고 보상 미지급은 모두 S1 이상으로 본다.
- 성공 기준: 첫 실행부터 1회 전투 종료 후 재실행까지 데이터 손실 없이 완료하고, 결제/광고 실패가 게임 진행을 막지 않는다.
- 검증 방법: 체크리스트 실행, 로그캣 수집, 이슈 템플릿 작성, 수정 빌드 재검증.
- 승인 상태: 계획 승인 대기.

#### QA 1차 계획/차단 기준

- 설치: Google Play 내부 테스트 또는 sideload 빌드가 설치/업데이트/삭제 후 재설치 흐름에서 충돌하지 않는다.
- 실행: 첫 실행 10초 이내 메인 또는 전투 화면 도달. 검은 화면, 무한 로딩, 권한 팝업 반복은 S0.
- 조작: 한 손 조작 기준 이동/선택/일시정지 터치 영역 오작동 없음.
- 전투 루프: 적 스폰, 자동 공격, 피격, XP 수집, 레벨업, 사망/결산, 재시작 가능.
- 모바일 가독성: 플레이어 탄/적 탄/XP/아이템이 서로 다른 색상과 실루엣으로 식별된다.
- 광고 실패: 광고 미로드, 네트워크 끊김, 광고 닫기, SDK 오류 시 보상 미지급 안내 후 게임 진행 가능.
- 결제 실패: 구매 취소, 네트워크 오류, 보류, 중복 탭, 상품 조회 실패 시 재화 중복 지급 없음.
- 저장 데이터 손실 방지: 전투 종료 직후 앱 강제 종료, 홈 전환, 배터리 절전 복귀 후 진행/재화/구매 상태가 보존된다.

#### QA 1차 초기 예상 이슈

- 이슈명: 적 탄과 플레이어 탄 색상 혼동
  - 재현 단계: 일반 전투에서 플레이어 자동 공격과 적 원거리 공격이 동시에 발생하는 장면을 30초 이상 플레이한다.
  - 기대 결과: 플레이어 탄은 청록/백색, 적 탄은 빨강/마젠타 계열로 즉시 구분된다.
  - 실제 결과: 실제 플레이 전. 색상 팔레트 미확정으로 혼동 가능성 있음.
  - 심각도: S1
  - 수정 담당: Visual Design Lead + Dev Lead
  - 재검증 결과: 대기
- 이슈명: 광고 실패 후 보상 버튼 잠김
  - 재현 단계: 네트워크를 끈 상태에서 보상형 광고 버튼을 누른 뒤 다시 네트워크를 켠다.
  - 기대 결과: 보상은 지급되지 않지만 버튼/상점/전투 복귀가 정상 동작한다.
  - 실제 결과: 실제 플레이 전. 광고 SDK 상태 복구 미구현 가능성 있음.
  - 심각도: S1
  - 수정 담당: Dev Lead
  - 재검증 결과: 대기

### 단계 15: Google Play 출시 체크리스트

- 단계명: 15. 출시 체크리스트
- 담당 에이전트: Dev Lead + QA Lead
- 목표: 개인 개발자 범위에서 Google Play Android 출시 제출에 필요한 빌드, 정책, 스토어, 수익화 항목을 빠짐없이 확인한다.

- 산출물: Google Play Android 전용 출시 체크리스트.
- 발견된 문제: 2026-05-05 기준 Google Play 제출 target SDK는 Android 15(API 35) 이상이 요구되며, Godot 4.3 Android 문서는 SDK 34 기반 설정을 안내한다. 빌드 담당이 실제 export preset과 Gradle target SDK를 반드시 확인해야 한다.

  - Google Play 제출은 AAB로 준비한다. APK는 실기/내부 배포용으로만 사용한다.
  - Play Billing Library는 지원 기간 내 버전을 사용한다. 2026-05-05 기준 v7은 2026-08-31까지 신규/업데이트 제출 가능, v8은 2027-08-31까지 가능하므로 신규 구현은 v8 우선 검토.
  - 개인 개발자 계정이 2023-11-13 이후 생성된 경우, production 신청 전 12명 이상 테스터가 14일 연속 opt-in한 비공개 테스트 요건을 일정에 반영한다.
- 성공 기준: Play Console 내부 테스트 업로드, 정책 양식 제출, 결제/광고 상품 검증, RC QA 통과 후 production 신청 가능 상태가 된다.
- 검증 방법: Play Console release 검증, pre-launch report, 내부/비공개 테스트, 결제 테스트, 광고 테스트, 데이터 보안 양식 리뷰.
- 승인 상태: 계획 승인 대기.

  - 구매 소유권은 로컬 저장만 신뢰하지 않고 Play 구매 조회로 복원 가능.
  - 업데이트 설치 후 마이그레이션 테스트.
  - 전투 종료, 보상 지급, 구매 승인 직후 앱 종료 테스트.
  - 손상 저장 파일 로드 시 전체 초기화 전 사용자 피해를 줄이는 복구 경로 제공.
- QA/출시 운영
  - S0/S1 open issue 0개.
  - known issue 목록은 사용자 피해, 재현율, 회피 가능성을 포함.
  - Play pre-launch report의 크래시/ANR/보안 경고 검토.
  - staged rollout 시작 비율과 rollback 기준 정의.

### 단계 16: 출시 승인 게이트

- 단계명: 16. 출시 승인 게이트
- 담당 에이전트: QA Lead + Dev Lead + Visual Design Lead
- 목표: 출시 후보가 아트, 기능, 수익화, 저장 안정성, 정책 기준을 모두 만족하는지 최종 판정한다.
- 구현/기획 범위: QA 1~3차 결과, Google Play 체크리스트, 알려진 이슈, rollback 기준, 고객지원 준비.
- 산출물: 출시 승인/차단 기준, 최종 산출물 12~14/16 커버리지 기록.
- 발견된 문제: 현재는 계획 단계이며 실제 승인 근거가 없다.
- 수정 지시:
  - S0: 실행 불가, 결제 소유권 유실, 저장 데이터 손상, Play Console 제출 차단, 전투 중 강제 광고는 무조건 출시 금지.
  - S1: 핵심 루프 진행 불가, 광고 보상 미지급/중복 지급, IAP 중복 지급, 전투 판독 불가, 25fps 미만 장기 하락은 수정 전 출시 금지.
  - S2: 일부 UI 잘림, 드문 시각 효과 깨짐, 비핵심 설명 오타는 risk acceptance 가능하나 목록화한다.
- 성공 기준: 모든 S0/S1 이슈가 재검증 완료이며, S2 이하는 사용자 피해와 수정 일정을 승인받았다.
- 검증 방법: QA 종료 보고서, Play Console 검증 결과, 결제/광고/저장 회귀표, 최종 스크린샷 리뷰.
- 승인 상태: 대기.

### 단계 18: 출시 후 모니터링 및 핫픽스 기준

- 단계명: 18. 출시 후 모니터링
- 담당 에이전트: QA Lead + Dev Lead
- 목표: Google Play 출시 후 초기 24시간/72시간 내 치명 이슈를 감지하고 staged rollout 또는 핫픽스 결정을 내린다.
- 구현/기획 범위: Play Console vitals, 크래시/ANR, 결제/광고 로그, 사용자 피드백, 저장 복구 문의, staged rollout.
- 산출물: 출시 후 모니터링 체크리스트와 핫픽스 기준.
- 발견된 문제: 출시 전 문서이므로 실제 운영 지표는 없다.
- 수정 지시:
  - 구매 성공 후 미지급, 광고 보상 미지급 다발, 저장 데이터 유실 신고, 특정 기기 실행 불가는 즉시 rollout 중지 후보.
  - 단일 기기군 크래시라도 결제/저장과 연관되면 S0로 승격한다.
  - 핫픽스는 저장 마이그레이션을 후퇴시키지 않아야 하며 versionCode 증가와 회귀 QA를 포함한다.
- 성공 기준: 24시간 내 S0 미발생, 72시간 내 crash/ANR 추세 허용 범위, 결제/광고 보상 문의가 재현 가능한 known issue로 정리된다.
- 검증 방법: Play Console vitals, crash logs, tester feedback, 고객 문의 태그, hotfix smoke test.
- 승인 상태: 계획 승인 대기.

## 최종 산출물 12~14, 16 커버리지

- 최종 산출물 12: QA 1차/2차/3차 체크리스트. 단계 12~14에서 계획/차단 기준과 초기 예상 이슈를 정의했다.
- 최종 산출물 13: 결제/광고 실패 케이스 검수 기준. 단계 12~16과 출시 체크리스트에 광고 실패, 결제 실패, 복원, 중복 지급, 보류/환불 케이스를 포함했다.
- 최종 산출물 14: 저장 데이터 손실 방지 검수 기준. 단계 9, 12~16에 저장 버전, 백업, 원자적 저장, 업데이트 마이그레이션, 구매 소유권 복구를 포함했다.
- 최종 산출물 16: Google Play Android 출시 체크리스트와 승인 게이트. 단계 15~16에서 Godot 4.3 빌드, Play Console 정책, 개인 개발자 테스트 요건, 출시 차단 기준을 정의했다.

## 심각도 기준

- S0: 출시/QA 진행 불가. 실행 불가, 제출 불가, 결제 소유권 유실, 저장 데이터 손상, 법/정책 위반, 전투 중 강제 광고.
- S1: 출시 차단. 핵심 루프 중단, 광고/IAP 보상 오류, 전투 판독 불가, 장기 프레임 저하, 업데이트 데이터 손실.
- S2: 출시 전 수정 권장. 특정 UI 잘림, 낮은 재현율의 비핵심 오류, 설명/현지화 오류.
- S3: 백로그 가능. 미세한 연출 품질, 낮은 영향의 편의 개선.
